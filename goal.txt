1. Project Overview
SecureWipe is a bootable drive sanitization utility designed primarily for wiping Windows-based computers during decommissioning or reuse workflows.

The tool will boot from USB into a lightweight Linux environment, detect installed storage devices, perform a cryptographic wipe process, verify wipe completion, and generate structured audit reports that are stored locally and uploaded to a centralized Git repository.

The project emphasizes:
• Reliability
• Operational consistency
• Forensic defensibility
• Maintainability
• Long-duration stability

The project does NOT prioritize polished UI/UX or enterprise-scale infrastructure.
2. Primary Project Goals
The student is expected to deliver a working prototype capable of:
1. Booting from USB on common Windows hardware
2. Detecting connected drives (SATA/NVMe/USB)
3. Identifying SSD vs HDD
4. Allowing selective drive selection for wiping
5. Executing a cryptographic wipe workflow
6. Performing wipe verification checks
7. Recovering gracefully from interrupted operations
8. Generating structured wipe reports
9. Uploading reports to a Git repository
10. Operating reliably for repeated use over extended periods
3. Core Functional Requirements
3.1 Boot Environment
• Boot from USB
• Support modern UEFI systems
• Attempt compatibility with Legacy BIOS where feasible
• Operate independently of installed operating system
• Recommended base: Ubuntu Live or Debian Live

3.2 Drive Detection
The application must:
• Enumerate connected drives
• Detect SSD vs HDD
• Collect:
  - Model
  - Serial Number
  - Capacity
  - Interface Type
  - SMART Information

Recommended tooling:
• lsblk
• smartctl
• sysfs
• blkid

3.2.1 Drive Selection & Safety Controls
The application must support selective wiping when multiple drives are detected.

Requirements:
• Display all detected drives clearly
• Allow operator selection of one or more drives
• Prevent wiping the boot USB device
• Require explicit confirmation before wipe begins
• Display serial numbers during confirmation
• Warn operators when multiple drives are selected

Example workflow:
Detected Drives:
[1] Samsung SSD 970 EVO - 1TB - NVMe
[2] WD Blue HDD - 2TB - SATA
[3] Kingston USB - 32GB - Removable (BOOT DEVICE)

Select drive(s) to wipe:
> 1,2

Type CONFIRM to continue.

3.3 Sanitization Workflow
Required workflow:
1. Generate temporary encryption key
2. Create LUKS2 encrypted container
3. Open encrypted mapping
4. Write across encrypted volume
5. Close encrypted mapping
6. Destroy LUKS header
7. Remove residual filesystem signatures

For HDDs:
• Perform final overwrite pass with zeros

Recommended tools:
• cryptsetup
• dd
• wipefs

3.4 Verification
Required checks:
• Confirm LUKS header removal
• Verify filesystem signatures are absent
• Perform random sector sampling
• Verify HDD overwrite contains zeros
• Collect SMART information before/after wipe

3.5 Recovery Handling
Requirements:
• Maintain JSON state file
• Detect incomplete wipe operations
• Allow operator to resume or restart jobs

3.6 Reporting
Required outputs:
• JSON report
• Text summary log

Reports should include:
• Timestamp
• Machine information
• Drive metadata
• Wipe method used
• Verification results
• Success/failure state
• Operator identifier (optional)

3.7 Git Repository Upload
The system must:
• Upload reports to a private Git repository
• Retry uploads if network unavailable
• Store reports locally until upload succeeds

• Avoid silent failures
• Produce readable logs

• Interruption detection

• Clear drive identification
